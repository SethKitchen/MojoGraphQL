# Benchmark results

Generated by `make bench` on 2026-10-19 for gql_http2. Do not edit this file by hand.

Each number is the time of one operation, in microseconds: the fastest of 5 rounds of at least one second each, after a warm-up. The speedup is the baseline time divided by the Mojo time. A speedup above 1.00x means that Mojo is faster. Every implementation runs every workload that its library can express. `n/a` means that the library cannot do the operation.

Mojo is the fastest on every workload. The smallest speedup is 1.13x, on `http2/roundtrip-small-json` against hyper 1.12.0 and h2 0.4.20 (Rust).

## Method

- Every program reads the same fixture bytes and runs one operation at a time.
- The lexer workloads read every token to the end of the file. apollo-parser also returns whitespace and comment tokens, because its tree is lossless. gql_language, graphql-js and graphql-go-tools skip them.
- The apollo-parser walks are the upstream `parse_query` and `parse_schema`. They visit the selection set of each top-level field, or the type of each object type field. The other implementations do the same visit over their own trees.
- apollo-parser builds a lossless syntax tree (CST). It has no printer, so it has no print results. A plain parse is `Parser::new(text).parse()` and a check that there are no errors.
- apollo-compiler parses with `ast::Document::parse`, which runs apollo-parser and converts the CST to an AST. It prints with the `Display` of the AST. It has no lexer of its own.
- graphql-go-tools reuses one parser and one document for all operations, as its benchmarks do and its documentation tells hot paths to do. `go-tools/Print` uses `Printer{}` into a reused buffer, as `BenchmarkPrint` does: a compact form on one line. The other print workloads use `PrintStringIndent` with two spaces, the layout of graphql-js. gql_language, graphql-js and apollo-compiler always print the multi-line layout, which is more output.
- gql_language and graphql-go-tools decode string values when a program reads them, not during the parse. graphql-js and apollo-compiler decode during the parse. The print workloads decode every string in all implementations.
